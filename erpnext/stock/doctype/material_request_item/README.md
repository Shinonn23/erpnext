Items requested in the parent Material Request.

Rate and Amount are the company-currency estimate and its quantity total. price_list_rate stores the catalog baseline used when the request was prepared. The company policy app controls which users may read or edit prices.

The six estimate_supplier / estimate_currency / estimate_rate / estimate_exchange_rate / estimate_source / estimate_price_date fields remain in the schema for historical requests only. They are hidden, read-only and not copied into new requests; new requests use the standard Rate and locked Estimated Buying Price List.

Demo / Borrow rows (Customer Demo, Borrow, Customer Borrow; Connect Diagnostics UX WP7, 19 Nov 2026): the requester names the Item and the quantity; the Stock team decides each row in the company app (Change Demo Acquisition, Decide release, Prepare Conversion). Once decided, the row shows its decision read only: `demo_acquisition_method` (the grid column "Supply") is shown when it holds a value, and an Asset row (`item_type` Fixed Asset) shows `asset`, `asset_name`, `asset_serial_number`, `source_location` and `target_location`, read only for these types (an Asset Transfer still picks its Assets). `assets/doctype/material_request/material_request.js` `configure_material_request_item_columns` adds the Supply column once a row is decided and the Asset column once a row is an Asset row; the app's `setup/grid_columns.py` keeps only the columns every type shares (item, qty, UOM) and the script adds the warehouse, rate and location columns of each type. A row stores only what applies: `before_validate` clears the warehouses and Storage Locations of an Asset row and the Asset fields of a Stock row, and `validate_demo_items` no longer copies the customer's Location onto a Stock row (it stays on the header). The app clears the same fields when it writes a decided row directly.
